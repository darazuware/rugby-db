# 10 ユース・学生・セブンズ／アージグレード代表 — Phase 5 設計

> 前提: 00の絶対原則（SSOT・null・source_url・検証ゲート）を全て適用。
> **P1〜P3完了後に着手。** 現行フェーズをブロックしない。

## 目的
- 高校・大学・セブンズ日本代表・U代表（U17/U18/U19/U20/U23）を名鑑化し、
  選手が成長してリーグワン/代表入りした時に経歴が自動で繋がるデータベースを先に作る。
- 「○○高校 ラグビー 出身選手」「U20日本代表 メンバー 2026」等のロングテールSEO。
- 既存の「同じ高校・大学の選手」リンク機能の強化（下記「つながりグラフ」）。

### 高校スコープ
- 花園出場校に限定しない。**激戦区の強豪校を都道府県横断で網羅**する。
- 対象都道府県（激戦区、随時追加可）:
  大阪・京都・兵庫・奈良・神奈川・東京・福岡・鹿児島・熊本・長崎・
  埼玉・千葉・茨城・愛知・大分・宮崎・北海道・秋田
- 各都道府県は `data/manual/hs_target_schools.json` で「収集対象校リスト」を明示管理する
  （全高校は追わない。強豪＝花園出場歴 or 各都道府県予選ベスト8常連 or 選抜/7人制常連 を人が選定）。
- 収集単位 = 学校ページの一覧行のみ（個別ページ・写真・生年月日なし。未成年ポリシー厳守）。

## 未成年の個人情報ポリシー（絶対）
- 掲載可: 氏名・カナ・所属校・学年・ポジション・大会出場記録（全て公式公表分のみ）
- 掲載禁止: 生年月日（学年のみ）・身長体重（高校生は非掲載、大学以上は公式発表分のみ）・
  出身中学・SNSアカウント・写真・AIイラスト
- 高校生の**個別ページは作らない**。学校ページ内の一覧行のみ。
  個別ページ化の条件: 大学進学後、またはU代表/セブンズ代表選出時。
- 削除依頼はメールフォーム経由で即時対応（04のフッターに窓口明記）。

## データ設計（01の拡張）
> **01との整合（済）**: education 配列・is_minor は 01 のPlayerスキーマに既にベースラインとして採用済み。P1移行時点で `name_raw`＋`school_id:null` で入り、school_id は本フェーズ(P5-1)で埋める。よって P5 で選手スキーマの破壊的変更は発生しない。team_id=null（学校/代表のみ所属）は 03 の条件付き必須で許可済み。
- `data/master/players/` に追加:
  - `sevens-national.json`（男女。`squad: "sevens_m" | "sevens_w"`）
  - `age-grade.json`（`squad: "u17"|"u18"|"u19"|"u20"|"u23"`）
  - `university.json` / `highschool.json`
- Player スキーマに追加フィールド（既存リーグの選手にも適用）:
```json
{
  "education": [
    {"school_id": "toin-gakuen", "type": "hs", "grad_year": 2024, "source_url": "...", "scraped_at": "..."}
  ],
  "is_minor": true
}
```
  - `is_minor: true` のレコードはサイト生成時に上記ポリシーのフィールド制限を**コード側で強制**（テンプレートに任せない）。
  - `education` は既存 unified DB の 出身高校/大学 文字列を school_id に正規化して移行。
- `data/master/schools/schools.json`: `{id, name, name_kana, type: "hs"|"univ", pref}`。
  表記ゆれ（例: 桐蔭学園/桐蔭学園高校）は `data/manual/school_aliases.json` で吸収。
- 同一人物の突合キー: `name_kana + education の school_id 重なり`。自動突合は候補提示まで、
  確定は `data/manual/player_merges.json` に人が記録（誤マージ防止）。

## つながりグラフ（既存機能の強化）
- **注意**: 現行実装（players/[...slug].astro）は生年月日/年齢から学年を推定しているが、
  未成年は生年月日を持たない（上記ポリシー）ため、**判定基準を `education.grad_year` に移行する**こと。
- 現行のページ内ハードコード（SCHOOL_MAPPING、±2/3年窓）は P5-1 の schools.json + school_aliases.json に置き換える。
- ビルド性能: 現行は選手ページ毎に全選手を走査（O(N²)）。学生追加で選手数が倍増するため、
  P5-4 で「学校→選手」インデックスを一度だけ構築して各ページはそれを引く方式に変える。
- 現行「同じ高校・大学」に加えて:
  - 在籍期間の重なり判定（`grad_year` から逆算）→「同期」「先輩・後輩」ラベル
  - 「U20同期」「セブンズ代表歴」バッジ
- 学校ページ = `/schools/{id}/`: 出身プロ・代表選手一覧 + 現役学生一覧（ポリシー準拠）。
  これがロングテールの受け皿。

## スクレイパー方針（02の拡張・低トークン運用）
- JRFUスコッド発表は記事HTML内の名簿リスト。構造が不定なため:
  1. Pythonで記事HTML取得 → 名簿らしきブロックを正規表現で粗抽出
  2. 抽出失敗時のみ Sonnet に「このHTML断片から {name, kana, school, position, grade} のJSON配列を抽出。無い値はnull」と粗抽出ブロックだけ渡す（全文を渡さない）
  3. 出力は 03 のスキーマ検証を通す。LLM出力も `source_url` 必須・null原則適用
- 大会名簿（花園・大学連盟）は年1〜数回の静的ページ → 手動トリガーのスクレイパーで十分。GitHub Actions常時監視はセブンズ/U代表の発表ページのみ（05に統合）。
