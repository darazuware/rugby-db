# 00 マスタープラン — rugbypicks 大幅刷新

> この docs/renewal/ 一式は、Sonnet / Opus が単独セッションで実装できる粒度の指示書。
> 実装AIは必ず本ファイル → 担当フェーズの指示書 → 09_TASKS.md の該当タスク、の順に読むこと。
> **それ以外のファイルを先回りで読まない（トークン節約）。**

## 目的
ラグビー選手名鑑サイト（Astro + Vercel）を「正確・自動更新・収益化可能」な状態に刷新する。
過去の失敗原因は **AIが事実（経歴・キャップ・移籍）を自由記述で書いたこと**。これを構造的に不可能にする。

## 絶対原則（違反したらそのPRは無効）
1. **SSOT（単一の正データ）**: サイトに表示される事実は全て `data/master/` のJSONから来る。JSONはスクレイパーだけが書く。人間もAIも手で事実を書かない。
2. **事実と文章の分離**: 選手・チームページの本文は「テンプレート＋JSONの値の穴埋め」で機械生成する。AIが経歴・成績・移籍の文章を創作することを禁止する。
3. **不明は null**: ソースに無い値は null のまま表示しない。推測・補完は禁止。
4. **出所の記録**: 全レコードに `source_url` と `scraped_at` を必須で持たせる。
5. **検証ゲート**: スクレイプ結果はスキーマ検証＋整合性チェックを通らない限りコミットされない（CIで強制）。

## スコープ
### 必須（Phase 1-3）
- **リーグワン 全ディビジョン（D1/D2/D3）** — ソース: league-one.jp 公式
- **Top14** — ソース: all.rugby
- **Super Rugby Pacific** — ソース: all.rugby
- **代表戦（日本代表中心＋対戦相手国スコッド）** — ソース: all.rugby + JRFU

### 条件付き（Phase 4、余裕があれば）
- URC / Premiership / NRL は **チームページ＋日本人選手・スター選手の個別ページのみ**。
  フルスコッド名鑑はやらない（精度リスクとメンテコストが高いため）。

### 有名選手の単独ページ
- 対象 = 代表キャップ保持者 ＋ `data/manual/featured_players.json` の手動リスト
- 写真は使わない。Instagram公式埋め込み（oEmbed）→ 無ければAIイラスト（06参照）

## 実装AIへの運用ルール（トークン節約）
- 1セッション = 09_TASKS.md の1タスク。完了条件を満たしたらコミットして終了。
- ファイルは必要な範囲だけ読む。data/ の巨大JSONは全読み禁止（`head` かPythonでサンプル確認）。
- 質問はしない。指示書に書いていない判断は「原則1〜5に沿う最も保守的な選択」をし、コミットメッセージに明記する。
- 動作確認コマンドは各タスクに書いてある。それ以外の探索的実行はしない。
